# Loom

### 手动网格框选（codex/manual-grid-selection）

点击菜单栏或绿点悬浮面板中的“网格框选”，在原目标窗口所在显示器显示全屏网格层。拖动选择一个或多个网格单元，松开鼠标后仅调整原目标窗口；不会自动选择或排布其他窗口。选区覆盖可用桌面，避开菜单栏与 Dock，反向拖拽和拖出边缘会正确吸附、裁剪。激活时鼠标所在格子立即显示一格大小的半透明白色圆角选框，白色虚线边框持续滚动；移动鼠标时预览跟随，按下并拖动扩展选区，松开应用。单击并松开可应用一格大小。Esc、右键、切换应用或显示器变化会取消。虚线动画在关闭时停止，并遵循系统减少动态效果设置。

设置 → 悬浮面板 → 框选网格使用原生下拉菜单选择行列数，可选 4、8、12……60，默认 12 列 × 8 行，独立于设置页的图标摆放网格。设置 → 快捷键 → 手动布局可绑定入口，默认不绑定。框选图标可拖动或隐藏。成功应用后可使用已有“还原”回到 Loom 首次调整前的位置；最小窗口尺寸由应用决定。需要辅助功能权限，系统全屏与不可调整的窗口不支持框选。

运行 `LOOM_SDK=/path/to/MacOSX.sdk zsh scripts/test-selection-grid.sh` 验证坐标计算、反向选择、边缘和小区域行为。叠层仅在唤起时创建，关闭后释放事件观察；没有空闲轮询。当前编译与逻辑检查通过，桌面自动化连接超时，实际拖拽、取消及还原效果仍待实机验证。

### 首次授权引导

首次启动显示原生引导窗口：“允许 Loom 管理窗口”，说明辅助功能权限用途，并提供“前往授权”“稍后设置”。点击授权后打开系统辅助功能设置，仅在本次引导授权会话中临时检测权限；授权成功后切换为“Loom 已准备就绪”，点击“开始使用”关闭。引导关闭或稍后设置会停止检测并记录已处理，下次启动不重复弹出；仍可从设置的权限页授权。旧版尚未授权且未处理过新引导的用户会显示一次；已授权的旧用户不打扰。

运行 `LOOM_SDK=/path/to/MacOSX.sdk ./scripts/test-permission-onboarding.sh` 可验证首次启动策略、授权切换、稍后设置及检测清理。

引导操作按钮上下排列，“前往授权”和“开始使用”共用放大的原生主按钮。点击“稍后设置”先显示提醒，说明可从“菜单栏 Loom 图标 → 设置 → 权限 → 打开系统设置”重新授权；点击“知道了”后关闭引导。授权状态切换使用 0.24 秒交叉淡入淡出，并遵循系统“减少动态效果”偏好。

面向 macOS 14+ 的原生菜单栏窗口管理工具。无账户、无网络请求、无窗口轮询。

## 构建与运行

应用图标以 `icon/Loom.icon` 为构建来源，需安装完整 Xcode、完成首次初始化并通过 `xcode-select` 选用。构建脚本使用 `actool` 直接编译分层图标，打包 `Assets.car` 和旧系统兼容的 `Loom.icns`，并使用编译器生成的图标声明；启动时不再用静态图片覆盖系统图标。图标外观遵循 `.icon` 文档设置及系统渲染。旧 `icon/应用图标.png` 留作原稿，不参与构建。菜单栏使用 `icon/顶部菜单栏图标.svg`，自动转为矢量 `MenuBarTemplate.pdf`，以 18pt 模板图像适配明暗背景。修改素材后重新构建即可，构建末尾会刷新 Finder 注册。

需要匹配的 Apple Swift 编译器和 macOS SDK：

```sh
./scripts/build.sh
open dist/Loom.app
```

应用为本机架构，使用临时签名，适合个人使用。建议复制至 `/Applications` 后再授权辅助功能和开启登录启动，避免后续移动路径导致授权失效。重新构建后，系统可能要求重新授权。

可用 `LOOM_SDK=/path/to/MacOSX.sdk ./scripts/build.sh` 指定 SDK。也可在正常的 Swift Package Manager 环境运行 `swift test`。`swift run` 不是推荐的使用方式：权限和登录启动需要完整应用包。

## 使用

点击菜单栏的四格窗口图标选择操作，或使用 Control + Option：← 左半屏、→ 右半屏、Return 最大化、C 居中、Backspace 还原、N 下一显示器。↑ 上半屏、↓ 下半屏。设置中可录制或清除全部快捷键；Esc 取消录制。快捷键注册失败会显示提示并保留旧配置。

首次启动会显示授权引导。在系统设置 → 隐私与安全性 → 辅助功能中启用 Loom，或选择“稍后设置”。未授权仍可通过菜单栏打开并编辑设置。登录启动默认关闭，通过 macOS ServiceManagement 注册。

还原记录仅存在于本次运行，连续布局保留第一次调整前的位置；显示器断开时会将还原位置约束到当前可用屏幕。显示器按从左到右、同列从上到下循环。窗口最小尺寸由目标应用决定，Loom 读取一次实际大小后定位，不循环强制调整。

## 验收清单

- Safari、Finder、系统设置、Electron 普通窗口：半屏、最大化、居中、连续调整后还原。
- 双屏不同缩放比例、负坐标、上下排列、跨屏窗口及外接屏断开后的还原。
- 改变 Dock 位置及自动隐藏状态后，布局使用最新可用区域。
- 无前台窗口、固定大小窗口、系统全屏、关闭窗口、权限撤销：显示提示且不崩溃。
- 快捷键重复、外部占用、清除、重启恢复；录制时不触发 Loom 操作。
- 菜单操作保留原前台窗口；设置关闭后仍常驻；登录启动开启、关闭并重登验证。

## 原生全屏幕

菜单“整个屏幕”通过辅助功能的 `AXFullScreen` 属性直接进入系统全屏空间，与“最大化”不同，不展开系统窗口菜单，也不添加人工等待。设置页可录制对应快捷键，默认不绑定。

左右布局使用已有的“左半屏 / 右半屏”，直接调整桌面窗口位置和大小。已移除原生左右全屏分屏的入口、快捷键及菜单调用路径；升级时清理已删除操作的绑定，其他快捷键保留。

实机需验证原生全屏进入、已全屏时不重复切换、权限撤销、不支持全屏的窗口及目标窗口关闭。macOS 自身的全屏切换动画仍由系统控制。

## Palette 实验功能（codex/palette-hover）

本分支新增绿点悬浮面板。授权辅助功能后，将鼠标停在前台应用窗口的绿色按钮上，默认 0.3 秒显示七个按钮：最大化、左半屏、右半屏、上半屏、下半屏、居中、还原。按钮有原生悬停与按下状态及操作提示，调用已有窗口管理逻辑，不使用系统分屏菜单。可见容器采用混合方案：非激活 NSPanel 承载自定义圆角与箭头轮廓，NSVisualEffectView 的 menu 材质提供原生模糊，保留 NSButton 交互及系统窗口阴影。

设置 → Palette 可启用/关闭功能、调整 0.15–1 秒的延迟和 30–44 pt 的按钮大小。设置会保存；本实验版默认开启。弹出前按住 Command 绕过 Loom 使用系统绿点菜单。弹出后保持原应用窗口激活，面板保持显示，鼠标移开、滚动或按修饰键不关闭；选择动作、点击内外空白区域或 Esc 时关闭。窗口关闭、桌面切换等目标失效情况仍会清理面板。

检测由鼠标事件驱动，命中测试最多约每 60 ms 一次；停在绿点后只安排一次延迟任务，面板关闭时无轮询。通过透明绿点命中层降低系统菜单同时触发的概率，并以 AX 菜单通知及仅在待弹出／已弹出期间运行的 100 ms 元数据检测补充互斥；系统菜单优先出现时取消或收起 Loom 面板。点击绿点会移除该层后转发原始鼠标按下事件，鼠标抬起由系统原路径处理。该机制属于实验实现，需验证自定义标题栏、Option 点击、快速双击、以及系统菜单是否仍会出现。未暴露标准辅助功能绿点的应用不会触发面板。

自动化检查：

```sh
LOOM_SDK=/path/to/MacOSX.sdk ./scripts/test-palette.sh
LOOM_SDK=/path/to/MacOSX.sdk ./scripts/test-layout.sh
```

实机验收：

- Safari / Finder / Codex：悬停绿点显示面板，操作落在原目标窗口上，面板弹出时原应用窗口保持激活；执行动作后仍操作原目标窗口。
- 延迟结束前移开不显示；弹出后鼠标移到其他区域仍保持显示；选择动作、点击空白或 Esc 后关闭。
- 普通绿点点击、Option 点击、Command 悬停仍可使用系统行为，没有事件重复或点击丢失。
- 权限撤销时不触发；重新授权后恢复；关闭开关立即移除透明层与事件监听。
- 多屏、不同缩放、负坐标、显示器断开：面板仍在可用区域内。
- 目标窗口关闭、切换、移动或调整大小时清理面板；系统原生绿点菜单不与 Loom 同时显示。

当前已编译并运行几何测试，因桌面自动化连接超时，以上真实鼠标交互尚未完成实机验收。

### Palette 网格布局

设置 → Palette → 布局预览现在是固定 10 列 × 6 行的 60 格编辑器，使用原生 NSCollectionView 提供拖拽与放置反馈。拖到空格会移动图标；拖到已有图标的格子会交换位置，不创建重复动作。拖出网格取消移动，不删除图标。提供“恢复默认布局”按钮。

布局自动保存在本机 UserDefaults，悬浮面板按已放置图标的最小行列包围区域显示，裁掉外围空行空列，保留区域内的空格和图标相对位置；设置页仍展示完整 10×6 网格。按钮大小设置同时作用于预览和实际面板。首次默认将七个动作放在中间一行；恢复默认仅重置网格，不改变快捷键、延迟或主题。

运行 `LOOM_SDK=/path/to/MacOSX.sdk ./scripts/test-palette-layout.sh` 可验证移动、交换、边界、持久化和损坏数据修复。真实拖拽及悬浮面板视觉仍需实机验收。

Palette 的按钮大小同时缩放图标，最小到最大约放大 47%，预览与实际面板一致。面板本体相对默认位置右移 24 pt，箭头屏幕坐标仍锁定绿点中心；屏幕边缘或窄布局时优先保持可见并限制偏移。

### 系统面板互斥与外观边界

系统菜单已出现时不显示 Loom；系统菜单后出现时 Loom 收起。检测结合 AXShownMenuUIElement、目标应用的菜单打开通知，以及绿点附近的浮层窗口边界与层级（不读取窗口内容）。不同 macOS 版本或应用可能有不同的窗口层级与辅助功能支持，需实机验证互斥行为。

当前试验已从 NSPopover 转为 NSPanel 混合外壳。常规圆角 12 pt、箭头高 10 pt，箭头始终对准绿点。浅色图标采用不透明 sRGB #313334，深色模式使用明亮图标；绕过模板图标的 Vibrancy 着色，保留原生按钮交互。背景使用原生 menu 模糊材质，随背后内容、系统版本与降低透明度设置变化，不能承诺在所有环境下逐像素一致。

混合面板增加浅蓝至近白的半透明渐变，叠在原生菜单模糊材质上；深色模式使用对应的深蓝灰渐变。按钮通过始终活跃的鼠标追踪区域提供蓝色圆角背景与白色图标的 hover 状态，鼠标离开时恢复原色，不影响目标窗口焦点。

## 原生多窗口排布

提供“双窗口左右排布”“双窗口上下排布”“三窗口排布”“四窗口排布”，分别调用目标应用原生“窗口 → 移动与调整大小”菜单中的“左侧与右侧”“顶部与底部”“左侧与四等分”“四等分”。由 macOS 选择其他窗口、执行桌面平铺并遵循系统平铺设置；不会用普通单窗口缩放替代，不进入 Split View。需要 macOS 15 或更新版本及辅助功能权限，实际命令可用性还取决于应用和系统版本。

入口位于菜单栏、设置 → 快捷键 → 多窗口排布、设置 → 悬浮面板 → 布局预览。默认不绑定快捷键；悬浮面板的左右与上下排布图标可分别拖动或隐藏。旧“双窗口排布”仅改显示名称，保留原快捷键和隐藏状态；升级时上下排布图标添加到附近空格，不移动现有图标。恢复默认布局时，第二行依次为居中、双窗口左右、双窗口上下、三窗口、四窗口、还原。全部隐藏时不弹出面板。

调用先激活保留的目标窗口，再在后台读取精确菜单路径并执行 AXPress；不会发送模拟键盘组合键。若应用延迟生成菜单，可能需要短暂展开原生“窗口”菜单。无法找到、菜单被禁用、目标关闭、前台窗口变化或权限未授权时明确报错。原生多窗口操作的恢复由系统“恢复上一个大小”负责；Loom 的“还原”仍只处理 Loom 自己记录的普通窗口调整。

验证：`LOOM_SDK=/path/to/MacOSX.sdk zsh scripts/test-native-arrangement.sh` 检查原生命令匹配及已有快捷键 ID 稳定性；`scripts/test-palette-layout.sh` 检查新旧配置迁移、拖拽、隐藏及边缘裁剪。实机已核对 Finder 的三个原生命令和 Loom 新入口；当前重编译的 Loom 显示辅助功能未授权，真实多窗口调用仍待重新授权后验证。
